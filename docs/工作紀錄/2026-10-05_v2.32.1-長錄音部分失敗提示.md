# 2026-10-05 — v2.32.1：長錄音有段落沒辨識出來時，讓使用者看得到

> 來源：v2.32.0 第三輪審查發現的既有問題（見 [v2.32.0 交接紀錄 §5](2026-10-05_v2.32.0-蘋果邊錄邊辨識與紀錄補洞.md)），
> 使用者指示在同一個 session 處理。

## 1. TL;DR

- 長錄音一段一段（約 10～12 秒）邊錄邊轉。**修補前**：某一段辨識失敗就被靜悄悄變成空白，使用者看不出少了一段；
  **尾段**當掉則整次錄音算失敗，前面轉好的幾分鐘全部不見
- 現在：成功的照樣貼上，並在四個地方告訴使用者：
  - **錄音小窗**閃 4 秒「N 段沒辨識出來」（使用者多半在別的 App 打字，主視窗被蓋住，只有這個浮動小窗跨 App 看得到）
  - **結果卡**多一個紅色「N 段沒辨識出來」標籤（之後打開視窗也查得到）
  - 「轉錄完成」提示後面加註；狀態列留一條提示（可開日誌）
  - 紀錄寫 `partial_transcription` 事件（只記段數，在貼上之前寫，才對得回是哪一次錄音）
- 全部失敗時顯示「辨識失敗」，不再誤說「未偵測到語音內容」（會讓人以為麥克風壞了）
- 順手修：狀態列提示原本**只有模型重新暖機才會收掉**，一掛上就一直掛著；改成新的錄音成功開始就收

## 2. 改了什麼

| 位置 | 改法 |
|---|---|
| `transcriber.is_failure_message()` | 系統訊息裡扣掉「沒講話／沒聲音」那兩句，其他「（…）」都算失敗。刻意反過來列：新增失敗訊息忘了登記，最壞是多跳一次警告，不會把失敗藏起來 |
| `gui._dispatch_stream_chunk` | 段落回失敗訊息或丟例外 → 記進 `_stream_failed` |
| `gui._run_transcription` | 切過段時尾段丟例外不再讓整次失敗；合併時數「失敗＋尾段失敗＋放開後等太久沒轉完」；掛 `failed_segments`／`total_segments` 在結果上 |
| `gui._on_transcription_done` | 一開始（貼上之前）記紀錄；提示文字（`_done_toast_text`）；回到閒置後顯示錄音小窗提醒與狀態列提示（`_notify_partial_failure`） |
| `gui._transition_to_recording` | 錄音成功開始時，狀態列若是提示就換回音量條（暖機進度條不動）；失敗清單在 generation 往前推之後才清 |
| `MiniRecordingWindow.show_warning` | 新增：顯示一句提醒、4 秒後自己收；期間開始新錄音會取消收起的排程 |
| `UtteranceBlockV2.set_result(failed_segments=)` | meta 行多一個紅色標籤（沿用狀態列提示的紅色 token） |

### 刻意的設計

- 段落數寫在「轉錄完成」同一則提示裡，不另外跳一則：提示都疊在同一個位置，另跳一則會跟「貼上失敗」互相蓋掉
  （審查實測：加註後的提示比「已貼入」寬，會露出左半截約 0.9 秒；所以主要靠錄音小窗與結果卡，提示只是輔助）
- 尾段當掉而且前面也沒有任何文字：照舊走「轉錄失敗」流程（提示、失敗原因都記得到），不走「部分失敗」
- 「（音樂）」「（笑）」這種整句括號的音效標記會被當成失敗（多提醒一次）。查過使用者 14,815 筆真實結果：
  整句括號 2,548 筆全是「沒講話」那兩句，0 筆音效標記，所以維持「沒登記的括號一律當失敗」
- 狀態列提示在回到閒置**之後**才放
- 失敗段數是給提示用的：段落剛好在截止那一刻結束時可能差一，所以夾在段數內

## 3. 驗證

- 新增 `tests/test_partial_failure_hint.py`（31 個）：先寫、確認修之前 16 個失敗（另 5 個是「沒失敗不能亂跳」的對照組）
- 對照檢查：兩批共 21 種「把修正拿掉」的改法，每一種都有測試轉紅
- 真視窗：結果卡標籤畫得出來、跟「校正」標籤並排不超出（728 寬的排只用到 577）；錄音小窗兩種寬度（220／140）
  都放得下提醒文字，顯示後會自己收起
- 全套：445 passed、1 xfailed

## 4. 審查（Sonnet × 2：正確性、使用者看得到與紀錄）

| 問題 | 處理 |
|---|---|
| 提示與狀態列都在主視窗裡，使用者在別的 App 打字時看不到；下一次按熱鍵就被收掉 | 加錄音小窗提醒與結果卡標籤 |
| 紀錄在貼上之後才寫，錄音編號已被清掉，對不回是哪一次錄音 | 改在貼上之前寫 |
| 尾段當掉、前面也全空時，從「轉錄失敗」變成「轉錄完成 · 0.0s」 | 照舊走轉錄失敗 |
| 合併時先拍快照再數沒轉完：中間剛好轉完的段落兩邊都不算（微秒級） | 先數再拍 |
| 失敗清單在 generation 往前推之前就清，上一次錄音的殘留段落可能寫進來（毫秒級） | 往前推之後才清 |
| **既有、另開工單**：開 AI 潤飾時，最後一段開頭會掉幾個字（接縫的假句號被拿掉後，切尾段的位置算錯） | 不在這次範圍；已開待辦卡片 |

## 5. 留給下一個人的坑

- 真的切段失敗很難在真機重現（要辨識引擎在長錄音中途出錯），這次全部是用替身驗的，**沒有真機實測**
- 狀態列提示改成「新錄音開始就收」會影響既有的「轉錄失敗」「麥克風無法啟動」提示：它們現在也會在下一次成功開始錄音時消失（原本要等模型重新暖機）
- 蘋果邊錄邊辨識（v2.32.0）不切段，不會走到這條路；只有退回切段時（Whisper、Qwen3、蘋果串流中途失敗）才會用到
