# 2026-10-04 — v2.31.4：麥克風打不開時自動改用內建麥克風

## 1. TL;DR

- 麥克風第一次打不開時，不再直接放棄：**重整清單 → 同一支再試（只在瞬間失敗時）→ 內建麥克風 → 系統預設**
- 「哪一支是內建」改成直接問 macOS（看連接方式），不靠名字猜
- 使用者設定改成**固定用內建麥克風**（`input_device = "MacBook Pro的麥克風"`，使用者資料、不在版控）
- 改用別支時的提示文字照實講用了哪一支

## 2. 事故經過（兩種不同的失敗）

### 2.1 10/3 21:10：EarPods 硬體起不來

按錄音後卡 5～8.5 秒，然後 `PortAudioError: Internal PortAudio error [PaErrorCode -9986]`。
系統日誌（`log show`，coreaudiod）同一時間：

```
HALS_UCRemotePlugIn.mm  Failed calling start_io on remote driver
HALS_IOContext_Legacy_Impl::IOWorkLoop: failed to start the hardware
_TellHardwareToStart ... returned error: 0x77686174
```

裝置是 `AppleUSBAudioEngine:Apple, Inc.:EarPods`，當時是**系統預設輸入**。

排除過的：
- **不是 macOS 27 升級**：升級後 10/2 20:31 還正常錄過 13 秒
- **不是 v2.31.3 的改動**：重開 App 載入新程式之前，舊的那個行程 21:10:43 就已經失敗；那次改的是轉文字，錄音一行沒動
- **不是權限**：tccd 沒有任何拒絕紀錄；而且權限被擋時 macOS 通常是給靜音，不是報錯

### 2.2 10/4 00:56：拔掉耳機後清單過期

拔掉 EarPods 後第一次按錄音，**4 毫秒內**失敗：`PortAudioError: Error querying device -1`。
PortAudio 啟動時把裝置清單拍成快照，耳機拔掉後快照裡已經沒有「預設輸入」。
11 秒後清單被重整（裝置監聽觸發），再按就正常錄了 69 秒。

### 2.3 為什麼舊邏輯兩個都救不了

v2.21.4 的補救只有一條：「**有指定裝置**時失敗 → 改系統預設」。
使用者用的是系統預設（`input_device = None`），失敗就直接放棄；而且從來不重整清單。

## 3. 修法

`recorder.py`：

| 步驟 | 做什麼 | 為什麼 |
|---|---|---|
| ① | `refresh_portaudio()` 重整清單 | 修 2.2 |
| ② | 同一支再試，**只在第一次是瞬間失敗時**（< `_SLOW_OPEN_FAIL_S` = 1 秒） | 慢慢失敗 = 硬體卡住，再試只會讓使用者再白等 5 秒 |
| ③ | 內建麥克風 | 實際出事時，系統預設往往就是那支壞掉的外接裝置，所以排在系統預設前面 |
| ④ | 系統預設 | v2.21.4 原本的退路，留作最後一道 |

另外：建好但啟動失敗的串流現在會先 `close()`——之後要重整清單、換一支再試，半開的串流會佔住裝置。

**認出內建麥克風**（`builtin_input_device_name`）：用 ctypes 問 CoreAudio 每個裝置的連接方式
（`kAudioDevicePropertyTransportType == 'bltn'`）且有輸入串流，再取名字。沿用 `start_device_monitor`
既有的 ctypes 寫法（專案沒裝 pyobjc 的 CoreAudio 綁定）。

不用名字比對的原因：名字會隨系統語言變；而且這台機器上有一個叫「MacBook Pro的揚聲器」、
卻帶 1 個輸入聲道的虛擬裝置，光看名字會認錯。

## 4. 使用者設定（不在版控）

使用者要求固定用內建麥克風。`~/.whisper_app/config.json` 的 `input_device` 從 `null` 改成
`"MacBook Pro的麥克風"`（備份：`~/.whisper_app/config.json.bak-2026-10-04`；對備份 diff 只改這一行）。

改的時候 App 正在跑——確認過 App **只在使用者手動改設定時存檔**（自動貼上開關、換模型、換語言、
換主題、設定視窗按儲存），關閉時不會存，所以直接改檔案不會被蓋掉；但**重開 App 之前若使用者
動了上述設定，App 會用記憶體裡的舊值（null）蓋回去**。

## 6. 意外發現

- **這台 Mac 的輸入裝置有 7 個**，其中兩個是使用者的 iPhone（接續互通相機的麥克風）、
  還有 BlackHole、Teams、iShot 的虛擬裝置。macOS 有時會自動把系統預設切到 iPhone——
  這也是「固定用內建」比「跟著系統預設」穩的原因。
- **EarPods 為什麼起不來，沒查到根因。** 系統日誌只說 USB 音訊驅動回「啟動失敗」。
  可能是線材、轉接頭、或 macOS 27 的 USB 音訊驅動；需要使用者換一條線或換一個孔再試才知道。

## 7. 留給下一個人的坑

1. **硬體卡住時，第一次嘗試本身仍要等 5～8.5 秒**——那是 macOS 在等硬體回應，App 端縮短不了。
   補救流程只保證「不會再多等一輪」。如果使用者的設定指向一支常常卡住的裝置，每次錄音都會先等這一段。
2. **`_SLOW_OPEN_FAIL_S = 1.0` 只有兩個資料點**（硬體卡住 5～8.5 秒、清單過期 4 毫秒），中間沒有實測。
3. **設定檔裡存的是名字。** 換電腦、改系統語言之後名字對不上，`set_device_by_name` 會退回系統預設
   ——此時補救流程的第 ③ 步（問 CoreAudio）仍然會在失敗時找到內建麥克風。
